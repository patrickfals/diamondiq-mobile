# DiamondIQ — Final One-Screen Expo UI

Project: diamondiq-mobile
Platform: React Native / Expo
Deadline: Today, November 20, 2026

Objective

Transform the existing AtBatScreen into one polished, demo-ready mobile experience.

Use the previously approved “How It Was Made” screenshot as the visual reference: dark stadium-broadcast styling, electric-blue highlights, large strike zone, compact matchup information, AI commentary, and an interactive visualization of the IBM agent workflow.

Do not build four separate screens.

Everything should happen within one primary screen, using two modes inside the bottom card:

AI Commentary — Default mode, showing the current at-bat story.

How It Was Made — Explains the agent workflow that produces the commentary.

Preserve the existing working Expo application, replay engine, baseball data, and pitch interactions.

1. Inspect the existing application first

Work only in diamondiq-mobile.

Inspect the actual project structure and locate:

AtBatScreen.tsx

useReplayEngine.ts

Existing strike-zone and pitch-detail components

src/data/ and available commentary cache files

src/theme/colors.ts

Existing types and data-loading functions

Current pitch-type color mapping

Reuse existing components and data structures wherever possible.

Do not create duplicate replay logic, duplicate pitch-data models, or unnecessary components.

2. Data sources

Commentary

Prefer src/data/commentary_cache_v2.json if it exists and contains usable entries. Otherwise, use the existing src/data/commentary_cache.json.

Expected entries are keyed by revealed pitch position and contain:

commentary_by_level: novice, learning, regular, expert

evidence_pitches

Use only cache files that actually exist. React Native/Expo requires statically resolvable JSON imports; do not use conditional require() statements referencing nonexistent files.

If an appropriate cache exists in diamondiq-api but not diamondiq-mobile, copy it only after verifying its contents and intended purpose.

Traces

Use src/data/trace_cache.json only if it exists.

Entries are keyed by pitch position and may contain:

events

capture_notes

trace_complete

run_id

Never fabricate missing trace data.

If no trace exists for the selected position, display an explicitly illustrative workflow without measured durations.

Important: Do not label historical, simulated, or placeholder commentary as a verified IBM execution.
